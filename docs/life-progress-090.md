# 0.9.0 · 训练周回顾与重量纪录

生活间在成长回忆下增加“这一周，留下了什么”：周一至周日的训练／饮食日期、已确认组数、实际计时时长、原训练历史，以及每个动作按日期汇总的最大记录重量。可以翻阅过去周，选择动作看变化，为一条原训练记录写相册纪念。

只读原训练与饮食库，不另建健康表单、成就账本或奖励机制。只用actualSets里的有效实际组；旧记录没有逐组数据就注明缺口，不用计划重量补齐。计时未知与真实零时长区分。负重器械动作按相同动作编号比较，排除辅助／弹力带、自重、拉伸和有氧；数值是用户录入的外部负重，不能代替力量或健康评估。

第一次有值只建立起点。同日合并最大值，不猜测先后；只有以后日期严格超过之前最大值才显示新纪录。平纪录、仅增加次数、查看旧数据和导入不会补发经验。切到过去周不会混入之后的纪录。源记录更正或删除后立即重算；已经主动保存的相册纪念仍由用户管理。

新增js/life-progress.js、js/life-progress-ui.js、css/life-progress.css，life.html装载并挂载。沿用现有生活间、人物与相册，原首页14份摘要、动作配图与分类保持。没有新运行依赖、后台轮询或新健康写入接口。按原存储变化刷新，原数据未变不重复生成列表。

参考[OpenGym公开训练历史说明](https://github.com/AalishMS/OpenGym)与[Ischys训练纪录流程](https://github.com/ischys-app/Ischys)；后者MIT许可。这里只参考交互，没有复制代码／素材，也不将Flutter或React Native框架塞入现有网页。

24项新增规则检查与原111项共135项通过；新增42项实际离线浏览器流程通过，包括原训练表单保存后回顾更新、编辑删除重算、关联真实相册、损坏数据保留、键盘焦点及360／390／1440宽度。已检查桌面与390实际App页面截图；扫描改动UI文件未报告规则命中。完整资源、原功能回归、Android构建与包校验见交付记录。不等于手机安装、后台或性能验收；独立微信源本轮未改。

设计复核：直接派生比多存一份成就事实更简单，也避免编辑后遗留错误纪录。每次变化仍扫描历史；十倍规模首先需要测量整文档读取和排序成本，本轮不借机更换原存储架构。尚未完成体重／营养完整复盘、自动目标达成、超级组／热身、常用餐和更多人物动作，不能把本轮当成整份任务书完成。
