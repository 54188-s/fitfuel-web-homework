# FitFuel 2.5D 返回包复核 · 2026-10-26

本轮保留人类分身、手绘生活间与暖色接地阴影。先修连续运行和工程交付问题，角色造型没有换成机器人，原桌面首页也没有重排。

## 返回包实际包含什么

FitFuel-2.5D-Task-Pack-20261026.zip 的压缩数据校验通过，含53个文件：10份Markdown、19份Python、9张截图、9份JSON、3份差异和3份文本。它是任务记录、差异和验证材料，不能独立运行网页或重新构建App。包内没有完整业务源码、原始人物和房间PNG，也没有Blender／GLB模型。

README列出的package-manifest.json和99-校验/MANIFEST.sha256未在ZIP中找到。下面的修复交付另附实际生成的逐文件摘要。输入包的脚本只作文本检查，未执行其中的归档、恢复或清理操作。

## 本轮修复

| 问题 | 观察到的结果 | 修复 |
| --- | --- | --- |
| 网页人物绘制少还原一层画布变换 | 同一画布第一次绘制后比例变成0.4166667，第二次0.1736111；连续播放出现房间套房间，人物可能消失 | 在人物缩放结束后还原，再画房间空间的接触阴影。保留原阴影颜色和方向 |
| 动画控制离房间太远 | App的开启动画按钮约在页面3808像素处；系统减少动态效果时首屏静止，容易误认为失效 | 开关移至房间上方，显示当前状态、暂停原因、保存失败和恢复方法 |
| 可编辑源与运行文件不同 | 输出工程scene.js仍是旧内容；App只同步了场景载荷，遗漏已有自动目标文件 | 从同一套已合并源码重建17模块，统一网页、App网页资源和Android包 |
| 原小程序集成测试依赖固定日期 | 记录写在10月23日，页面读取实际日期，26日运行误报今日零条 | 只固定测试页面的日期；产品仍按用户当地日期工作 |
| App资源清单写死旧版本 | 生成器一直写0.8.0，与当前安装包不符 | 从App工程package.json读取版本 |

静态／隐藏与实际训练暂停的优先级保持。点击开启动画不会替用户恢复暂停的真实训练，也不确认组数、改历史或增发经验。

## 还没有做好的地方

| 优先级 | 具体缺口 | 下一次怎么验收 |
| --- | --- | --- |
| 高 | 翻书、用餐和休息的姿态仍主要由站立纸片人物摆动完成，手、书、桌椅接触不自然 | 按阅读／坐姿休息／用餐分别做关键姿态；近景检查手部接触、脚底和椅面，连续播放检查遮挡 |
| 高 | 陪练只有八类节奏，深蹲幅度和腿部折叠仍简化；推类也不能准确演示卧推 | 每次补少量明确动作，以原动作库示意图核对关键帧；未知动作保留准备姿态。不要把347动作目录写成347套已完成动画 |
| 中 | 390宽度下房间人物较小，场景细节难看清；区域移动也没有完整家具绕行 | 做人物近看和返回全景；按椅子、桌子和训练器械划出可走区域，验证往返路径 |
| 中 | 目标算法使用已记录的饮食和训练，漏记会影响校准；完整营养／体重复盘、热身／超级组、常用餐仍未补齐 | 将数据完整性提示与算法校准单列复核，继续复用原健身模块 |
| 待验 | 手机安装、照片选择与系统分享、后台和帧率没有真实设备证据 | 在实际Android手机执行升级、留影、切后台和长时间运行；浏览器模拟不能替代 |

现有素材足以继续细化2.5D，不需要为了修这些问题加入新的3D引擎。人物与家具接触应先通过少量专门姿态解决，再决定是否扩大骨骼系统。十倍场景数量下，手写姿态映射和遮挡规则会先难以维护；本轮没有擅自重构。
