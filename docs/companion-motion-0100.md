# 0.10.0 · 人类分身按动作陪练

原训练页开始训练后，每个动作旁可以选择“分身跟练这个动作”；修改该动作的次数、重量或完成勾选，也会将陪练切到它。回到生活间能看到对应动作名称、该动作已确认的组数、匹配的原动作图示入口，以及推、拉、上推、下肢、核心、手臂、踏步或舒展的节奏。分身使用原人类图集和2.5D房间，不增加机器人或另一套训练表单。

这是八类陪练节奏，并非347种动作的精确教学动画。例如卧推与其他推类共用推的节奏，深蹲、腿举等共用下肢节奏；具体技术继续看原动作库图示。未识别的动作保留准备姿态，不猜一个动作冒充。只在已填写正负重且器械为哑铃／壶铃时显示简化手持配件；不会把自重或所有器械都画成举哑铃。

陪练位置保存在原fitfuel_training会话的可选focusRow字段中。它不勾选训练组、不改计划结构、不生成历史、不结算经验或卡路里，也不重置休息截止时间。旧会话缺少字段时只读选取未完成动作，不自动迁移；取消或完成后换计划不会被旧位置锁住。旧程序会忽略这个可选字段。

完成一组仍先显示休息，暂停会停止陪练，恢复／结束休息后继续当前动作；静态模式冻结选定姿态，隐藏模式保留全部记录功能。切页和重开从原草稿恢复。训练停止后清除实际陪练投影，只有用户明确保存才产生历史与原有成长反馈。

修改文件：fitfuel-course/js/workout.js、workout-ui.js、workout-room.js、css/workout.css、css/life.css；engineering/life-src/core/index.js与companion的index.js／index.wxml／scene.js，重建原17模块life-source.js。源图片、动作目录、食品目录、原首页与游戏奖励规则保持。独立微信小程序的50份源本轮未改，只同步统一网页与Android封装。

技术选型核对[DragonBonesJS官方仓库](https://github.com/DragonBones/DragonBonesJS)及其MIT许可，参考分层骨架与贴图复用思路。当前已有分肢图集和Canvas绘制，直接补父子关节变换，无需加入新的动画引擎或运行依赖。另核对[OpenGym原仓库](https://github.com/DuarteSantos8/openGym)与[Forge](https://github.com/bndct-devops/forge)的训练流程，只作交互参考，没有导入代码、素材或其服务端框架。

验证：新增21项原草稿聚焦／失败保留／恢复／动作映射／静态姿态规则，加原135项共156项通过。新增67项实际离线浏览器检查覆盖八类人物、原训练按钮、编辑切换、暂停／休息／重开、正确图示、无自动完成、无健康篡改、静态与隐藏及1440／390／360宽度。检查了八类人物、桌面与窄屏房间及训练截图；一次合并修正把动作说明收回原状态区，避免桌面空洞。没有靠更换主题或重排首页掩盖问题。其他回归与Android／解压验证另见交付报告。

设计复核：原草稿是唯一实际训练状态，人物只读投影；聚焦是UI位置，没有另建人物训练账本。相同图集的分肢变换比逐帧新增图片简单，也保留外观换装。动作更多时首先需要逐类审查映射和遮挡，不能据这八类节奏宣称精确覆盖所有训练。原健康整文档、跨标签并发与移动端帧率问题仍须测量，本轮不借机改架构。
